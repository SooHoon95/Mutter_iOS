# Mutter 하네스 운용

지침·자동메모리·작업 문서를 쓰고 고칠 때의 규칙. 기능 코드 규칙은 `mutter-architecture`·`mutter-conventions` 등을 따른다.

배경: Opus 5 세대는 스스로 판단·검증·완결한다. 촘촘한 금지 나열·일괄 검증·적극 위임 지시는 토큰만 늘린다. 그래서 규칙을 **판단 기준**으로 쓴다.

## 규칙은 판단형으로 쓴다

- 새 규칙(CLAUDE.md 항목, 스킬 문구, 자동메모리)은 "언제 적용하고 언제 적용하지 않는지"를 같이 적는다. 예외가 있으면 규칙 안에 쓴다.
- 규칙에는 **왜**(어떤 실제 사고에서 나왔는지)를 한 줄 남긴다.
- 기존 규칙은 실제 충돌·오작동이 확인됐을 때만 손댄다. 일괄 재작성하지 않는다.
- **예외 — 도메인 하드 제약은 조건 없이 쓴다**: 서버 계약(RPC·에러 코드) 웹·Android와 동일 유지, 비밀값(`Sensitive.xcconfig`·`*.p8`·`GoogleService-Info.plist`) 커밋 금지, 런타임 동작 검증("컴파일 통과" ≠ "검증"), 사용자 노출 문자열 L10n, 커밋 단위 분리, 마케팅 발행은 `/marketing-approve`로만.

## 작업 문서 — `tasks/`

| 파일 | 용도 |
|---|---|
| `tasks/todo.md` | 현재 작업 계획 + 리뷰. 끝난 작업은 `tasks/archive/`로 옮긴다 |
| `tasks/lessons.md` | 최근·고유 교훈(세션 시작 시 검토) |
| `tasks/lessons-archive.md` | 1개월 이상 지났거나 스킬·자동메모리로 흡수된 교훈 |
| `tasks/archive/` | 완료된 계획·리포트(`git mv`로 이력 보존) |

**todo.md 포맷** — `## 현재 작업 — <제목> (YYYY-MM-DD)` 아래 `- [ ]` 항목, 끝나면 `### 리뷰`에 변경 요약·검증 증거. 새 작업을 시작할 때 이전 작업은 아카이브로 보낸다.

**lessons.md 포맷** — 최신을 위로.

```
### YYYY-MM-DD — 한 줄 제목
- 상황: 무엇을 하다 무엇이 잘못됐나
- 교정: 사용자가 어떻게 바로잡았나
- 규칙: 같은 실수를 막을 검증 가능한 행동 규칙
```

교정은 재발 방지 규칙으로 일반화해 기록한다. 같은 실수가 반복되면 기존 규칙을 강화한다. 기술적으로 오래 쓸 교훈은 해당 스킬로 옮기고 lessons에서는 아카이브한다(스킬이 단일 진실 소스).

## 사고 강도(effort)

- 기본은 **low~medium**. 파일 몇 개 읽고 판단이 서는 일에 최대 강도를 쓰지 않는다.
- 올리는 경우: 원인 불명 버그, 여러 모듈·저장소(iOS·Android·웹)에 걸친 설계, 되돌리기 어려운 변경, 서버 계약·인증 같은 하드 제약 판단.
- 올렸으면 왜 올렸는지 한 줄로 밝힌다.

## 리뷰 보고

- 찾은 것은 **전량 보고**하고, 사용자에게 보이는 요약은 **심각도로 필터**한다(기본 HIGH 이상). LOW/INFO는 목록만.
- 확신이 없다고 빼지 않고 **확신도**(확실 / 추정 / 미확인)를 적는다.
- 각 지적에 근거 출처(스킬·규칙·`파일:라인`)와 심각도(CRITICAL / HIGH / MEDIUM / LOW / INFO).
- 리뷰를 서브에이전트에 위임할 때 이 규율을 프롬프트에 그대로 쓴다.

## 문서 분량

- 상한은 **계획·스펙 15KB, 리포트·요약·리뷰 6KB**. 넘길 이유가 있으면 문서 안에 근거를 적는다.
- 채우기 섹션 금지 — 내용 없는 "리스크"·"향후 과제", 빈 표, 헤더만 남은 템플릿 블록을 만들지 않는다.

## 검증·위임 강도

프로젝트 `CLAUDE.md` §2(Subagent Strategy)·§4(Verification Before Done)가 단일 진실 소스다. `.claude/CLAUDE.md`(OMC 관리)의 일괄 강제 문구는 재동기화로 원복되므로 손대지 않고, 루트 `CLAUDE.md`의 우선 선언으로 이긴다.

## Codex 사본

마케팅·영상 에이전트는 Codex가 실행한다. `.claude/agents/`가 원본이고 `.codex/agents/*.toml`은 `scripts/ai/sync_codex_agents.py`가 생성한다(손으로 고치지 않는다). `AGENTS.md`와 `.agents/skills/`는 Codex용 지침 사본이다 — 스킬 이름·구조를 바꾸면 Codex 사본도 같이 갱신할지 확인한다.

## 하네스 변경 후 확인

- `CLAUDE.md`·커맨드가 참조하는 스킬 이름이 `.claude/skills/*/SKILL.md`의 `name:`과 일치한다(dangling 0).
- 각 SKILL.md frontmatter에 `name`·`description`이 있고 `name`이 디렉터리명과 같다.
- 실제 세션(`claude -p`)에서 스킬 목록에 노출되고, 대표 프롬프트에 맞는 스킬이 호출되는지 확인한다.
