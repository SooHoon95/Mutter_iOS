# 영구 편지권 · 관리자 — 서버 계약 (iOS · Android · 웹 공용)

서버 마이그레이션 `letter-app/supabase/migrations/0036~0041`과 Edge Function 4개의 계약.
설계: `docs/superpowers/specs/2026-11-11-permanent-letter-ticket-design.md` (9절 우선).

모든 RPC는 PostgREST `rpc/<이름>`. 표에 없는 기존 RPC는 시그니처·반환 형태가 그대로다.

## 상태

편지의 접근 상태 `state`는 넷 중 하나다.

| state | 뜻 | access_until | delete_at |
|---|---|---|---|
| `permanent` | 기간 제한 없음(기존 편지·영구 편지권·관리자) | null | null |
| `open` | 무료 기간 안. 아직 아무도 안 열었으면 시각이 둘 다 null | 잠기는 시각 또는 null | 삭제 예정 시각 또는 null |
| `locked` | 무료 기간이 끝남. 편지권을 붙이면 다시 열린다 | 잠긴 시각 | 삭제 예정 시각 |
| `gone` | 유예도 끝남. 되살릴 수 없다 | — | — |

- 무료 기간(`free_days`, 지금 7일)은 **편지 단위**로 하나만 센다. 소유자가 아닌 로그인 사용자가 처음 본문을 받은 순간부터다.
- 보낸 사람(소유자)은 편지가 존재하는 한 항상 자기 편지를 연다.
- 일수(`free_days`, `grace_days`)는 `get_my_entitlements`가 준다. 코드에 14·30을 박지 않는다.

## 오류 코드 (RPC 예외 메시지)

| 메시지 | 뜻 | 화면 |
|---|---|---|
| `LOGIN_REQUIRED` | 이 편지는 로그인해야 열린다(익명 호출) | 봉투 화면 → 로그인 → 같은 편지로 복귀 |
| `LETTER_LOCKED:<ISO8601 UTC>` | 무료 기간이 끝났다. 뒤의 시각은 삭제 예정 시각 | 잠김 화면("○월 ○일까지 다시 열 수 있어요") |
| `LETTER_GONE` | 유예까지 끝났다 | "더 이상 열 수 없는 편지예요" |
| `NO_TICKET` | 편지권 잔액 부족 | 구매 화면(앱) / "뮤터 앱에서 살 수 있어요"(웹) |

기존 코드(`TOKEN_NOT_FOUND`·`LINK_REVOKED`·`LINK_EXPIRED`·`NOT_YET_REVEALED:<ISO>`·`WRONG_PASSWORD`·
`LETTER_NOT_FOUND`·`AUTH_REQUIRED`·`FORBIDDEN`)는 그대로다. 검사 순서는
토큰 → 회수 → 만료 → **로그인 요구** → 예약 공개 → 암호 → 편지 존재 → **잠김/삭제**.

## RPC

| RPC | 호출자 | 인자 | 반환 |
|---|---|---|---|
| `get_letter_by_token` (기존) | anon·로그인 | `p_token text, p_password text` | 기존 키 + `is_permanent boolean`, `access_until timestamptz\|null`, `is_mine boolean`(호출자가 보낸 사람 본인인가 — 0041, 키가 없으면 false로 본다) |
| `get_letter_cover` | anon·로그인 | `p_token text` | 아래 "봉투" |
| `get_letter_access_states` | 로그인 | `p_letter_ids uuid[]` | `[{letter_id, state, access_until, delete_at, kept_by_recipient}]` — 내가 보냈거나 받은 편지함에 가진 편지만. `kept_by_recipient`는 0041부터 항상 false다(쓰지 않는다) |
| `get_letter_readers` | 소유자 | `p_letter_id uuid` | `[{user_id, nickname, first_opened_at, last_opened_at, open_count}]` 처음 연 순. 소유자 아니면 `FORBIDDEN` |
| `get_my_entitlements` | 로그인 | 없음 | `{is_admin, tickets, paid_enabled, free_days, grace_days, warn_days}` — `warn_days`(지금 2)는 닫힘 예고를 며칠 전부터 보일지. 키가 없으면 2로 본다 |
| `get_my_ticket_history` | 로그인 | 없음 | `[{created_at, delta, reason, letter_title}]` 최근 순. `reason` ∈ `purchase`·`use`·`grant`·`refund` |
| `make_letter_permanent` | 소유자 | `p_letter_id uuid` | void. `FORBIDDEN`·`NO_TICKET`·`LETTER_GONE` |
| `keep_received_letter` | 로그인 | `p_token text, p_password text` | void. 링크 오류들 + `NO_TICKET`·`LETTER_GONE`. 성공하면 받은 편지함에 들어간다. **잠기기 전(`open`)에도 쓸 수 있다** |
| `is_admin` | 로그인 | 없음 | boolean |

- `make_letter_permanent`·`keep_received_letter`는 이미 영구인 편지에 부르면 차감 없이 성공한다.
- 관리자는 차감 없이 영구가 된다.
- `p_password`는 암호가 없어도 **키를 생략하지 말고 null을 보낸다**(Android: DTO에 `= null` 기본값 금지 —
  생략되면 PostgREST가 함수를 못 찾는다).

### 봉투 — `get_letter_cover`

본문 없음, 열람 기록 없음. 로그인 전 화면과 잠김 화면에 쓴다.

```json
{ "sealed": true }
```
토큰 없음·회수·만료·암호 걸림·예약 공개 전·삭제함 편지는 전부 이 모양이다(이유를 구분할 수 없다).

```json
{
  "sealed": false,
  "template_id": "classic-serif",
  "title": "…",
  "sender_nickname": "…" ,
  "state": "open",
  "access_until": null,
  "delete_at": null,
  "login_required": true
}
```
`login_required`는 "이 편지는 로그인이 필요한가"이며 호출자의 로그인 여부와 무관하다.
`sender_nickname`·`access_until`·`delete_at`은 null일 수 있다.
`sender_nickname`은 보낸 사람이 탈퇴했으면 `탈퇴한 사용자`다.

### 화면 노출 규칙

- `paid_enabled == false`이고 `is_admin == false` → 편지권 관련 UI(프로필 항목·구매·"영구 편지로 만들기")를 전부 숨긴다.
  상태 표시(○일 남음·자물쇠)는 `state`가 `permanent`가 아닌 편지에만 나오므로 따로 숨길 필요가 없다.
- `is_admin == true` → 구매 UI를 숨기고 편지에는 "영구"만 표시한다.

### 보내기 전 선택(보낸 사람) — 세 플랫폼 같은 규칙

보낸 사람이 결제를 **먼저** 고르게 한다. 받은 사람의 간직하기는 이걸 지나친 편지를 위한 보완이다.

- **언제 보이나**: 발송 직전 화면(링크 발급 화면, 연결 상대에게 보내기 화면)에서 아래가 모두 참일 때.
  1. 그 편지의 `state == open` (무료 기간 규칙 대상이고 아직 영구가 아님)
  2. `paid_enabled == true` (관리자의 편지는 처음부터 `permanent`라 해당 없음)
  3. 그 편지에 아직 발급된 링크가 없고, 이 화면에서 "14일 편지"를 고르지 않았다
- **모양**: 제목 "어떻게 보낼까요?" 아래 선택지 둘을 **라디오로 고르고, 맨 아래 버튼 하나로 진행한다**(선택지를 누르는 것만으로는 아무 일도 일어나지 않는다. 확인 팝업 없음).
  고르기 전에는 링크 발급 폼(암호·예약·발급 버튼)을 보이지 않는다. 기본 선택은 영구 편지.
  1. **영구 편지** (먼저) — "받는 분이 기간 제한 없이 간직해요" · "편지권 1장" · "보유 편지권 {n}장"
  2. **{free_days}일 편지** — "받는 분이 처음 연 날부터 {free_days}일 동안 열려요" · "무료"
  버튼 문구는 선택에 따라 "영구 편지로 보내기" / "{free_days}일 편지로 보내기". 영구가 선택돼 있고 편지권이 있으면 버튼 위에
  "링크를 만들거나 보낼 때 편지권 1장이 사용돼요".
- **편지권은 실제로 보낼 때만 쓴다(하드 규칙).** 영구 편지를 고르는 것만으로는 `make_letter_permanent`를 부르지 않는다.
  고르고 나서 링크를 만들지 않으면 편지권만 나가기 때문이다. 클라이언트는 선택을 화면에 머무는 동안 기억했다가,
  `issue_link(..., p_permanent => true)` 또는 `send_to_connection(..., p_permanent => true)`로 보낸다. 서버가 **같은 트랜잭션에서**
  편지권 1장을 쓰고 링크·발송을 만든다 — 어느 한쪽이 실패하면 둘 다 일어나지 않는다.
  `p_permanent`는 기본값이 false다. 영구가 아니면 보내지 않아도 되고, **0041 이전 서버에는 이 인자가 없으므로 true일 때만 보낸다.**
- **영구를 고르고 버튼을 누르면**: `tickets > 0`(또는 관리자)이면 선택을 기억하고 발급 폼·연결 상대 목록을 연다. 그 위에
  "영구 편지로 보내요 / 링크를 만들거나 보낼 때 편지권 1장이 사용돼요"와 글자 버튼 "다시 고르기"(선택 카드로 돌아간다)를 보인다.
  발급·발송이 성공하면 "영구" 표시로 바뀐다. `NO_TICKET`이면(그 사이 편지권이 없어짐) 결제 안내 시트를 띄운다.
  `tickets == 0`이면 앱은 **결제 안내 시트**(아래, 구매만)를 띄우고 구매가 끝나면 위와 같이 진행한다. 웹은 "편지권은 뮤터 앱에서 살 수 있어요"를 보이고 {free_days}일만 고를 수 있다.
- **{free_days}일을 고르고 버튼을 누르면**: 발급 폼을 연다(안내 "받는 분이 처음 연 날부터 {free_days}일 동안 열려요."는 그대로). 선택은 화면에 머무는 동안만 기억한다 —
  링크를 만들지 않고 나갔다 오면 다시 묻는다.
- 링크가 이미 있는 편지(이미 보낸 편지)는 선택 카드 없이 "영구 편지로 만들기 · 편지권 1장" 버튼만 보인다. 문구가 편지권 1장을 말하므로
  확인 팝업 없이 `make_letter_permanent`를 부르고, 편지권이 없으면 결제 안내 시트를 띄운다.
  **이 버튼은 링크가 없는(아직 안 보낸) 편지에는 보이지 않는다** — 보내기 전에 편지권이 쓰이게 되므로. 그런 편지는 "다시 고르기"로 바꾼다.
- `paid_enabled == false`면 아무것도 바뀌지 않는다(선택 카드 없음).

### 받은 사람의 간직하기 — 세 플랫폼 같은 규칙

받은 사람(로그인, 소유자 아님)은 무료 기간 안에도, 잠긴 뒤에도 자기 편지권으로 편지를 간직할 수 있다(`keep_received_letter`).
보낸 사람에게 "편지권을 써 달라"고 알리는 간직 요청(0040)은 없앴다. 읽는 도중에는 끼어들지 않고, 화면에는 "간직하기"만 쓴다
(편지권 1장은 확인 단계에서 보인다).

**간직 버튼을 보이는 조건**(아래 ①②③ 공통)
- 보낸 사람 본인(`is_mine == true`)에게는 ①②의 안내·버튼을 모두 보이지 않는다(자기 편지는 보낸 편지 상세에서 영구로 만든다).
- 앱: `tickets > 0 || paid_enabled || is_admin`. 잔액이 0이면 누를 때 결제 안내 시트(아래)가 뜬다.
- 웹: `tickets > 0 || is_admin`. 아니고 `paid_enabled`면 버튼 대신 "편지권은 뮤터 앱에서 살 수 있어요".
- 둘 다 아니면 버튼 없이 날짜 안내만 남는다.

**편지권이 있을 때의 확인**(팝업은 쓰지 않는다)
- ①② 편지 끝의 글자 버튼: 누르면 **같은 자리가** "편지권 1장을 사용해요. 보낸 분이 편지를 지워도 내 편지함에는 남아요." + [취소] / [간직하기]로 바뀐다
  (작은 글자 버튼 한 번에 편지권이 쓰이지 않게).
- ③ 잠김 화면의 "편지권으로 간직하기": 문구가 편지권을 말하므로 바로 진행한다. 버튼 아래에 같은 안내 문장을 미리 보인다.
- 편지권이 없으면 ①②③ 모두 확인 없이 곧바로 결제 안내 시트를 띄운다.

성공하면 본문이 그대로 열려 있고(잠김 화면이었다면 열리고) 안내가 "간직한 편지예요"로 바뀐다.

1. **① 편지 맨 끝** — 본문·사진이 끝난 자리에 작은 한 줄. `state == open`이고 `access_until`이 있을 때.
   "이 편지는 {M}월 {D}일까지 열려요" + 글자 버튼 "계속 간직하기". 영구 편지(`is_permanent`)에는 아무것도 없다.
2. **② 닫히기 `warn_days`일 전부터** — 기존 닫힘 예고("이 편지는 {n}일 뒤 닫혀요") 옆에 "간직하기" 버튼.
   남은 날 ≤ `warn_days`일 때 보인다(예전의 고정 3일 대신).
3. **③ 잠긴 뒤** — 잠김 화면의 "편지권으로 간직하기". "보낸 분께 알리기"는 없앤다.
4. **④ 받은 편지 목록** — 상태 표시("{n}일 남음"·"닫힘")만. 버튼은 두지 않는다.

### 결제 안내 시트(앱) — 편지권이 필요한데 없을 때 어디서나 같은 화면

편지권이 필요한 동작(보내기 전 선택의 영구 편지, "영구 편지로 만들기", 받은 사람의 간직하기 ①②③)을 눌렀는데 **편지권이 없으면** 이 시트 하나가 뜬다.
편지권이 있으면 뜨지 않는다(그 자리에서 바로 쓴다). 프로필의 편지권 화면(잔액·내역)과는 다른 화면이다.

- **형태**: 보던 화면 위로 아래에서 올라오는 시트. 높이는 내용만큼. 끝나면 내려가며 그 자리로 돌아온다(편지·음악은 뒤에 그대로).
- **내용**(위에서 아래로): 제목 · 한 줄 설명 · 요점 두 줄 · "보유 편지권 {n}장" · 상품 선택(라디오: 편지권 1장 / 5장, 가격) · 기본 버튼 · "취소".
- **문구는 누가 열었는지에 따라 다르다**

  | | 보내기 전(아직 안 보낸 편지) | 이미 보낸 편지 | 받는 사람 |
  |---|---|---|---|
  | 제목 | `영구 편지로 보내기` | `영구 편지로 만들기` | `이 편지 간직하기` |
  | 설명 | `받는 분이 기간 제한 없이 간직해요` | 같음 | `기간 제한 없이 계속 열 수 있어요` |
  | 요점 1 | `시간이 지나도 닫히지 않아요` | 같음 | `닫힌 편지도 다시 열려요` |
  | 요점 2 | `내가 편지를 지워도 받은 분의 편지함에는 남아요` | 같음 | `보낸 분이 편지를 지워도 내 편지함에는 남아요` |
  | 버튼(구매) | `편지권 구매하고 계속하기` | `구매하고 영구 편지로 만들기` | `구매하고 간직하기` |
  | 버튼(잔액이 생긴 뒤) | `계속하기` | `편지권 1장으로 만들기` | `편지권 1장으로 간직하기` |
  | 구매 뒤에 하는 일 | **없음**(편지권은 발급·발송 때 쓰인다) | `make_letter_permanent` | `keep_received_letter` |

- **버튼을 누르면**: 고른 상품 구매(`verify-purchase`까지) → 위 표의 "구매 뒤에 하는 일" → 시트가 닫히고 호출한 화면이 상태를 다시 받는다.
  보내기 전이면 영구 편지를 고른 상태로 발급 폼이 열린다. 구매를 취소하면 시트는 그대로다. 구매는 됐는데 사용이 실패하면
  오류 문구를 보이고 버튼이 "편지권 1장으로 …"로 바뀐다(편지권은 남아 있다). 구매·사용 중에는 시트를 쓸어내려 닫을 수 없다.
- 스토어 상품을 받지 못하면 "지금은 편지권을 살 수 없어요."를 보이고 버튼을 끈다.
- 구현은 화면 모듈과 분리된 한 곳에 둔다(iOS `Feature/Ticket`의 `TicketCheckoutView`). 호출하는 화면은 "무엇을 위해"(보내기·간직)만 넘긴다.
- **웹**에는 결제가 없어 이 시트가 없다. 편지권이 없으면 "편지권은 뮤터 앱에서 살 수 있어요"만 보인다.

### 삭제는 계정 단위 (0041)

- **보낸 사람이 지우면** 자기 보낸 편지·삭제함에서만 다룬다. 이미 받은 사람(받은 편지함에 가진 사람)은 계속 연다.
  아직 안 받은 사람과 로그인 없이 읽던 사람에게는 링크가 `LETTER_NOT_FOUND`로 닫힌다. 삭제함에서 되돌리면 다시 열린다.
- **영구 삭제·삭제함 30일 경과·탈퇴**는 보낸 사람 쪽에서 끊는 것이다. 받은 사람이 가진 편지는 남는다.
- **보낸 사람이 탈퇴한 편지**는 `sender_nickname`이 `탈퇴한 사용자`로 온다(`sender_id`는 값이 그대로 온다).
- **탈퇴한 상대에게는 보낼 수 없다.** `get_my_inbox`는 `sender_gone`, `get_counterparts`는 `gone`(둘 다 boolean)을 내려준다.
  true면 받은 편지함의 "답장"과 주고받은 화면의 "편지 쓰기"를 숨긴다. 필드가 없으면(서버 반영 전) false로 본다.
- **받은 사람이 지우면** 지금처럼 자기 받은 편지함에서만 빠진다.
- 받은 사람이 간직한 편지를 보낸 사람이 지워도 영구가 풀리지 않는다 → 환급도, 삭제 경고도 없다.
- 클라이언트가 고칠 문구: 보낸 편지 삭제 확인("이미 받은 분의 편지함에는 남아요"), 탈퇴 안내("보낸 편지는 받은 분의 편지함에 남아요").
- 링크 회수(`revoke_link`)는 그대로다 — 받은 사람의 접근까지 끊는 수단은 회수다.

## Edge Function

### `verify-purchase` — 편지권 구매 검증·지급 (앱 전용)

`POST /functions/v1/verify-purchase`, `Authorization: Bearer <사용자 JWT>`

| 플랫폼 | 본문 |
|---|---|
| iOS | `{"platform":"ios","jws":"<StoreKit 2 Transaction의 jwsRepresentation>"}` |
| Android | `{"platform":"android","productId":"mutter.ticket.1","purchaseToken":"…"}` |

- `200 {"granted": true, "tickets": 5}` — `tickets`는 지급 후 잔액.
- `200 {"granted": false, "tickets": 5}` — 이미 지급된 영수증. **성공이다.** 앱은 이때도 거래를 finish/consume 한다.
- 오류 `{"error":"<코드>"}`: `401 unauthorized` · `403 not_tester` · `400 bad_request` · `400 invalid_receipt` ·
  `400 unknown_product` · `501 store_mode_unavailable` · `501 android_verify_unconfigured` · `500 internal`.
- 앱은 **200을 받은 뒤에만** 거래를 finish(iOS)/consume(Android) 한다. 그 외에는 거래를 남겨 두고 다음 실행 때 다시 보낸다.
- 상품: `mutter.ticket.1`(1장), `mutter.ticket.5`(5장). 소모성.
- 지금은 테스트 모드다: `purchase_testers`에 든 계정만 지급된다(그 외 `403 not_tester`).

### `duplicate-letter` — 같은 내용으로 한 통 더 보내기

`POST /functions/v1/duplicate-letter`, `Authorization: Bearer <사용자 JWT>`, 본문 `{"letterId":"<uuid>"}`

- `200 {"letterId":"<새 편지 uuid>"}` — 본문·테마·음악·사진이 복제된 새 편지. 무료 편지로 시작한다(원본이 영구여도).
- `401 unauthorized` · `404 letter_not_found`(남의 편지 포함) · `400 bad_request` · `500 copy_failed`.
- 새 편지는 링크가 없다. 이어서 기존 발송 흐름(링크 발급 또는 연결 상대에게 보내기)을 탄다.

### `letter-photo-urls` (기존)

수신자 모드 요청에 로그인 사용자의 `Authorization`이 있으면 그 권한으로 게이트를 지난다.
`403 {error}`에 `LOGIN_REQUIRED`·`LETTER_LOCKED:<ISO>`·`LETTER_GONE`이 올 수 있다. supabase SDK의
`functions.invoke`는 로그인 세션의 JWT를 자동으로 싣는다.

## 푸시

data에 `type`과 `letter_id`가 있다.

| type | 받는 쪽 | 제목 | 언제 | 탭하면 |
|---|---|---|---|---|
| `letter_lock_soon` | 보낸 사람 | 편지가 곧 닫혀요 | 잠기기 `warn_days`일 전(편지당 1회) | 그 보낸 편지의 상세 |
| `letter_locked` | 보낸 사람 | 편지가 닫혔어요 | 잠긴 뒤(편지당 1회) | 그 보낸 편지의 상세 |
| `received_lock_soon` | 받은 사람(간직할 수 있는 계정만) | 받은 편지가 곧 닫혀요 | 잠기기 `warn_days`일 전(편지당 1회) | 그 받은 편지를 연다 — data에 `token`이 함께 온다 |

보낸 사람이 지운 편지는 보낸 사람에게 알리지 않는다. Android 알림 태그는 `letter_id`를 써서 서로 덮어쓰지 않게 한다.
`letter_keep_request`·`letter_kept`(0040)는 없어졌다.

## 문구 (세 플랫폼 동일)

| 키 | 문구 |
|---|---|
| 닫힘 예고(받은 사람, 남은 기간 ≤ `warn_days`일) | `이 편지는 {n}일 뒤 닫혀요` (당일이면 `이 편지는 오늘 닫혀요`) |
| 잠김 화면 제목 | `보관 기간이 지난 편지예요` |
| 잠김 화면 본문 | `{M}월 {D}일까지 다시 열 수 있어요.` |
| 잠김 화면 버튼(앱, 로그인) | `편지권으로 간직하기` |
| 잠김 화면 안내(웹, 잔액 없음) | `편지권은 뮤터 앱에서 살 수 있어요` |
| 보내기 전 선택 제목 | `어떻게 보낼까요?` |
| 보내기 전 선택 1 | `영구 편지` / `받는 분이 기간 제한 없이 간직해요` / `편지권 1장` · 버튼 `영구 편지로 보내기` |
| 보내기 전 선택 2 | `{free_days}일 편지` / `받는 분이 처음 연 날부터 {free_days}일 동안 열려요` / `무료` · 버튼 `{free_days}일 편지로 보내기` |
| 보내기 전 보유 표시 | `보유 편지권 {n}장` |
| 영구 선택 확인 | `편지권 1장을 사용해요` |
| 삭제 대상 | `더 이상 열 수 없는 편지예요` |
| 봉투 버튼 | `편지 열기` |
| 봉투 안내 | `로그인하면 편지가 열려요` |
| 보낸 사람 버튼 | `영구 편지로 만들기 · 편지권 1장` |
| 목록 상태 | `영구` / `{n}일 남음` / `닫힘` |
| 링크 발급 화면 안내 | `받는 분이 처음 연 날부터 {free_days}일 동안 열려요.` |
| 사본 | `같은 내용으로 한 통 더 보내기` |
| 열람자 행 | `{닉네임} · {M}월 {D}일에 열어봄` (닉네임 없으면 `이름 없는 사용자`) |
| 받은 사람이 편지권 쓸 때 확인 | `편지권 1장을 사용해요. 보낸 분이 편지를 지워도 내 편지함에는 남아요.` |
| 편지 끝 안내(받은 사람) | `이 편지는 {M}월 {D}일까지 열려요` · 버튼 `계속 간직하기` |
| 닫힘 예고 옆 버튼 | `간직하기` |
| 간직한 뒤 안내 | `간직한 편지예요` |
| 보낸 편지 삭제 확인(보탤 문장) | `이미 받은 분의 편지함에는 남아요.` |
| 탈퇴 안내(보탤 문장) | `보낸 편지는 받은 분의 편지함에 남아요.` |
| 탈퇴한 보낸 사람 | `탈퇴한 사용자` (서버가 내려준다) |
| 편지권 남은 계정 탈퇴 | `남은 편지권 {n}장이 사라져요.` |
| 편지권 화면 제목 | `편지권` |
| 편지권 잔액 | `{n}장` |
| 편지권 설명 | `편지권 1장으로 편지 한 통을 기간 제한 없이 간직할 수 있어요.` |
| 편지권 부족 | `편지권이 없어요` |
