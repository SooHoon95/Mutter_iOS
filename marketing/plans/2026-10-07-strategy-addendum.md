> 기준 문서: `marketing/plans/2026-09-16-channel-strategy.md`, `.agents/product-marketing.md`, 주간 루프(`scripts/marketing/weekly.sh`), `marketing/plans/2026-10-07-cost-report.md`

## 2. 보강 내용

### 2-1. 네이버 검색 채널 (원칙 1)

한국에서 "음악 편지 보내는 법", "노래 선물 방법", "고백 편지 앱" 같은 검색은 App Store가 아니라 **네이버**에서 먼저 일어난다. 9월 전략은 이걸 "느리다"며 1편으로 미뤘는데, 블로그 글은 한번 상위에 오르면 몇 달간 무료 유입이 쌓이는 자산이라 비중을 올린다.

| 항목 | 내용 |
|---|---|
| 주기 | 월 2편(1편은 시즌, 1편은 상시 방법형) |
| 구조 | 원문 방식 그대로: 메인·서브 키워드 + 타깃 + 글 목적(정보/비교/전환) → 소제목·FAQ 먼저 → 카피라이터 초안 → 사람이 사례·사진 보강 |
| 키워드 조사 | 네이버 검색광고 API의 키워드 도구(월간 검색량, **무료**, 광고 계정만 있으면 됨). 키워드를 받기 전까지는 네이버 자동완성·연관검색어로 대체 |
| 길이·형식 | 2,500~3,500자, 본문 이미지 5~8장(앱 화면·편지지 테마), 마지막에 웹 링크(`utm_source=naver&utm_medium=blog`) |
| 담당 | `mutter-copywriter`에 `naver_blog` 형식 추가, 키워드 플랜은 `mutter-aso-analyst` |
| 발행 | 네이버 블로그는 공식 글쓰기 API가 없다 → 초안을 붙여넣기용으로 큐에 둔다 |
| 비용 | 0원 |

**첫 글 후보**: ① "카톡으로 노래 한 곡 담은 편지 보내는 법"(방법형) ② "기념일 선물 대신 음악 편지 — 받는 사람은 앱 설치 없이"(비교형) ③ "빼빼로데이 편지 문구 + 노래 추천"(시즌형, 11/11)

### 2-2. 참여형 테스트 — "나에게 어울리는 편지 노래는?" (원칙 4b)

한국에서 심리테스트·성향 테스트는 공유가 가장 잘 되는 형식이고, 뮤터의 핵심(노래 + 편지)과 그대로 맞물린다. 원문의 involve.me(유료) 대신 웹에 직접 만든다.

| 단계 | 내용 |
|---|---|
| 유입 | 인스타·스레드·블로그 링크 → `/test` |
| 참여 | 질문 6~8개(보내고 싶은 사람, 하고 싶은 말, 지금 기분 등) |
| 결과 | 편지지 테마 7종 중 하나 + 어울리는 노래 분위기 + 편지 첫 문장 예시. 결과 카드는 OG 이미지로 공유 가능 |
| 전환 | "이 편지지로 편지 써 보기" → 웹 작성 또는 스토어(`ct=quiz`) |
| 측정 | 테스트 시작·완료·공유·CTA 클릭(기존 `track()` 훅) |
| 비용 | 0원(웹 기능, 개발 약 1~2일) |

이건 마케팅 루프가 아니라 **웹 기능 개발**이라 별도 작업으로 잡는다(우선순위 높음).

### 2-3. 성과 피드백 루프 + SNS 응대 (원칙 3·4a·7c)

지금 주간 루프는 "무엇을 올릴지"는 정하지만 "올린 것이 먹혔는지"를 모른다.

| 보강 | 방법 | 비용 |
|---|---|---|
| 게시물 성과 수집 | 인스타·스레드 연결 후 Graph API Insights(도달·저장·공유·프로필 방문·링크 클릭)를 `marketing/data/social/<date>.json`으로 수집하는 스크립트 | 0원 |
| 카피에 반영 | 카피라이터가 초안 전에 지난 4주 성과 상위 3개를 읽고 형식·첫 줄을 참고(성과 하위 형식은 줄임) | 0원 |
| 댓글·DM 응대 초안 | 신규 댓글을 수집 → 답글 초안을 큐에 → 승인 시 게시. 부정 댓글은 항상 사람 검토 | 0원 |
| 제품 지표 | Supabase 집계 RPC(발송·열람·가입·두 번째 편지) — 비용 보고서에서 보류한 항목을 **우선순위 상향** | 0원 |
| 주간 리포트 | 위 세 가지를 "콘텐츠 성과", "제품 지표" 절로 추가 | 0원 |

**선행 조건**: 인스타 프로페셔널 계정 + Meta 개발자 앱 연결(사용자 작업 약 20분).

### 2-4. AI 검색·웹 검색 기본기 (원칙 5)

검색 결과 상단의 AI 요약(네이버 AI 브리핑, 구글 AI 개요)과 ChatGPT·Perplexity 같은 답변 엔진은 **읽을 수 있는 텍스트**가 있는 페이지만 인용한다. 지금 웹은 본문이 자바스크립트로만 그려져서 크롤러에게 사실상 빈 페이지다.

| 보강 | 내용 | 비용 |
|---|---|---|
| `robots.txt` · `sitemap.xml` | 지금은 둘 다 앱 HTML이 돌아온다. 정적 파일로 추가, `/l/*`(편지)는 계속 차단 | 0원 |
| `llms.txt` | 뮤터가 무엇이고 무엇을 하는지 답변 엔진용 요약 | 0원 |
| 구조화 데이터 | 랜딩에 `SoftwareApplication` JSON-LD(이름·설명·스토어 링크·가격 무료) | 0원 |
| 랜딩 본문 정적화 | `index.html`의 `<noscript>`/정적 섹션에 한 줄 소개·기능·FAQ 텍스트를 넣어 크롤러가 읽게 | 0원 |
| AI 노출 점검(월 1회) | 루프가 "음악 편지 앱 추천", "노래 선물 앱" 등 질문으로 웹 검색해 뮤터 언급 여부·맥락을 기록(`marketing-skills:ai-seo`) | 0원 |
| 네이버 서치어드바이저 | 사이트 등록·사이트맵 제출(사용자 작업 5분) | 0원 |

### 2-5. 이미지 크리에이티브 템플릿 (원칙 2)

| 보강 | 내용 | 비용 |

### 2-6. 참여 이벤트 (원칙 6) — 유료 선택

| 형식 | 예시 | 예상 비용 |
|---|---|---|
| 인증 이벤트 | "뮤터로 편지 보내고 캡처 인증 → 추첨 10명 커피 기프티콘" | 커피 기프티콘 약 4,500원 × 10명 = **약 4.5만 원/회** |
| 테스트 공유 이벤트 | 2-2 테스트 결과 공유 + 댓글 → 추첨 | 같은 수준 |
| 추첨 | 직접 만든 무작위 추첨 스크립트(참여자 CSV → 시드 고정 추첨, 결과 공개) | 0원 |

인스타 이벤트는 Meta 프로모션 가이드라인(인스타 공식 후원 아님 고지, 참여 조건 명시)과 경품 고지(제세공과금 등)를 지켜야 한다. **리뷰 0건 상황에서 가장 빠르게 첫 사용자 반응을 만드는 수단**이라, 테스트(2-2) 오픈 시점에 1회 시도를 권한다.

### 2-7. App Store 인앱 이벤트 (추가 발견)

App Store Connect의 "인앱 이벤트"는 검색 결과와 투데이 탭에 이벤트 카드로 뜨는 **무료 노출면**이다. 시즌(빼빼로데이·크리스마스·발렌타인)을 프로모션 텍스트로만 쓰던 것을 이벤트 카드까지 확장한다. 최대 14일 전부터 노출 가능, 심사 필요(통상 1일). 담당: `aso-skills:in-app-events`. 비용 0원.

## 3. 원문 툴을 쓰지 않는 이유

| 원문 툴 | 대체 | 이유 |
|---|---|---|
| ChatGPT / Claude | 이미 사용 중(에이전트 4개) | — |
| Surfer SEO | 네이버 검색광고 키워드 도구(무료) + `marketing-skills:seo-audit` | Surfer는 구글 중심·유료. 한국은 네이버가 우선 |
| ImagineArt | Hyperframes + Playwright 템플릿 | 무료, 브랜드 토큰을 코드로 고정 |
| Predis.ai / Hootsuite | 주간 루프 + 공식 API 발행 | 월 $20~100대 유료, 우리 루프가 같은 역할 |
| Coupler.io | 수집 스크립트 + 주간 리포트 | 데이터 출처가 적어 통합 툴이 과함 |
| involve.me | 웹에 직접 만드는 테스트 | 유료, 뮤터 테마·음악과 깊게 붙이려면 직접 만드는 게 낫다 |
| Otterly.ai | 월 1회 AI 노출 점검(웹 검색) | 유료, 지금 규모엔 수동 점검으로 충분 |
| 기프티쇼 추첨기 | 자체 추첨 스크립트 + 기프티콘 구매 | 추첨은 무료로 가능, 경품만 구매 |
